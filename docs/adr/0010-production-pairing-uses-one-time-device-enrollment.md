# Production pairing uses one-time Device enrollment

A distributable R1 never bootstraps from the current trusted-operator Relay offer. A trusted Paseo client creates a five-minute, one-time enrollment code that grants no command authority; R1 and the trusted client verify the same device code and requested scopes before the daemon issues a long-lived, revocable grant bound to that R1 identity. Each connection exchanges that grant for a short-lived, automatically rotated Device session after revalidating its current scopes and security gates. The grant persists until explicit revocation, device reset, or loss of a required security capability; routine expiry applies to Device sessions, not periodic re-enrollment. Revocation immediately invalidates all derived sessions. Denial, expiry, or cancellation leaves no half-authorized credential, and this enrollment protocol is explicitly new work rather than an existing Paseo capability.
